# X 社区运营工作台（X Community Ops Hub）

面向 X（Twitter）创作者与社区运营者的**Java 服务端 + 内嵌 X 原生风前端**。系统实行**「X 官方授权登录 · 每人仅查本人账号 · 当天数据按小时核验」**机制，登录后可按 **24小时 / 48小时 / 7天 / 30天** 四个周期一键切换查看本人 5 大核心社区运营模块：

1. **发帖与回复活跃度看板**：支持按月（30天单日趋势）、按周（7天星期趋势）、按48小时（逐时节奏）查看原创发帖、主动暖场回复、引用/转推构成、回复/发帖比、主推平均公开互动率（ER%）与运营健康分。
2. **推友双向互动率深度拆解**：一对一拆解与全量排行榜联动，直观对比「我去评论 : 他来评论」、「引用比」、「@提及比」、「对方互动回礼率（对方互动 ÷ 我方互动）」与「社交精力占比」，自动分层 `双向奔赴` / `铁粉主动捧场` / `我方主动暖场`。
3. **未回关关注关系体检**：比对关注与粉丝名单，筛出「我关注但未回关」、「关注我但我未回关」、「互关推友」；叠加当前周期互动频次智能识别 **高粉大V防误删（≥2.5万粉）**、**我去互动仍未回关**、**普通号零回访建议清理**，支持按最近关注、亲密度、粉丝数量排序与一键直达主页管理。
4. **内容诊断**：短推/图文视频/长推 Thread 体裁转化对比、高影响力推文复盘流。
5. **社区铁粉圈层与晒单战报卡**：自动提炼「核心铁粉圈（Core Yappers）」、「待回访固粉清单（防冷落提醒）」与「活跃互暖伙伴」，支持随维度一键导出 **30天 / 7天 / 48小时战报** 高清 PNG 战报图与发推文案。

## 访问限制与当天数据刷新

- **登录授权且仅限本人查询**：`xops.require-login-self-only` 默认为 `true`。未登录请求 `/api/analyze` 返回 `401`；已登录用户仅可查询自己 OAuth 绑定的账号，用户名参数越权返回 `403`；账号归属以稳定用户 ID 校验，同名不同 ID 的数据不返回、不合并。缓存、使用状态和浏览器白名单按 ID 隔离，新持久化目录为 `users/by-id/<用户ID>/`；旧用户名目录仅经 ID 和用户名校验后复用。用户名已变更时明确阻断，需确认账号并迁移旧用户名历史，不自动合并。
- **当天刷新**　打开或刷新实时报表、点击“检查更新”或切换周期，页面都会向服务端检查本账号已入库的数据。服务端显示快照时间、最近一次完整更新时间、本人动态及入站互动的覆盖情况和待更新指标数。滚动 24 小时的两条数据流均已覆盖、窗口内帖子指标均已核验时，一小时内复用这批数据。到期或首次读取旧缓存时，从上次位置补入新动态和互动，同时按帖子 ID 更新赞、评、转发、书签和浏览数。页面会在同一账号、同一周期内接着读取有进展的批次，每次操作最多 20 批。如上游没有进展或本批失败，会保留已入库的进度；已尝试但未返回的帖子显示为本轮暂不可得，下个小时再查。已覆盖的旧时段仍可能有漏帖，热更新另用 Latest 搜索轮换抽查最近一天的一个 6 小时时段，每轮最多一页。
- **覆盖范围与名单完整性**：TwitterAPI.io 的时间线和提及流均覆盖目标时间，才算该窗口完成；上游分页、超时或预算限制导致未完成时，保留已有数据和游标，不把缺口当作已覆盖。重复游标、缺少结果数组和无效日期不代表取完；短时间缺口也保留，只有新增覆盖才算继续取得进展。单个流或分片失败时，已成功且日期有效的在途页面仍保存其覆盖，避免丢失已付费进度；降级状态继续阻止本批发起新的页面请求。官方 X API 当前只采集有界首屏快照，覆盖范围以实际取得的时间段为准。明确覆盖为 0 天时保留 0，不按请求窗口填成完整。关注与粉丝名单分别记录是否完整；分页结束但名单唯一数量与账号计数不一致，也按完整性存疑处理。TwitterAPI.io 普通粉丝分页成功结束但人数不足时，会在原同步时限内额外取一次粉丝 ID 列表，并仅补查最多 20 个缺失 ID 的资料；仅当 ID 列表已结束、唯一数量与资料总数一致且最终身份集合完全相等时才标为完整。两次补采均为有界付费读取，无额外重试；不可用身份、接口错误或未完成继续保留缺口。名单仍存疑时，TwitterAPI.io 会对关注名单中未出现在粉丝结果的对象补查双方关系；明确结果可正常归为互关、未回关或粉丝关系，只有无法确认的对象保留未知。关注名单完整且其中所有关系均已确认时，回关率可为完整结果，同时继续提示总粉丝名单的缺口。
- **逐人关系核验**：读取 `check_follow_relationship`，`source_user_name` 为本人、`target_user_name` 为对方；只接受成功响应中的布尔 `following`（本人关注对方）与 `followed_by`（对方关注本人）。每次同步最多 100 个候选、最多 4 个并发，遵守现有共享限流与同步时限；不自动重试。接口按人计费，目前公开标价每次 100 credits；时间或额度限制、错误及缺字段仍为未知，不据此建议清理。证据记录稳定 ID 和核验时间，构造新快照时超过 300 秒不再作为已核实关系；新图谱刷新或失败降级清除旧证据，同图谱扩窗可复用。未核验对象超过单批限制时，点击“继续核验关系（N）”按同一上限补查两个方向的未知关系，只查一批，不自动循环；名单过期或身份变化时需先刷新。实际请求的尝试时间单独保存用于轮转，失败对象不会永远占住前 100 位，也不把尝试记录当作关注证据。关系状态是查询时点事实，非永久保证。[接口契约与价格](https://docs.twitterapi.io/api-reference/endpoint/check_follow_relationship)
- **指标新鲜度**：报表窗口以资料快照为固定终点；续传过程中，指标按各批响应接收时间记录，读数可能晚于窗口终点。页面“指标最近采集”只表示最近 24 小时窗口中有可靠采集时间的成功指标的最近一次读数，不代表全部指标在同一时刻测量；旧缓存无法确认实际读数时间时显示未确认。当天按 ID 补读每批最多 50 条，24 小时以外的历史指标保留上次实测时间。历史推文指标每次热更新最多同步 1 批、每批最多 50 条；按最近尝试时间轮转，同龄记录优先补齐缺指标的独立主推和引用，串推楼层不冒充独立主推。指标批读取只尝试一次，必须在本轮原同步软截止点前获准发出（排队后会再次检查）；获准后，当天指标批读取最多等待 25 秒，历史指标批最多等待 15 秒。已过截止点不发请求，上游失败仍保留旧已知值及未知状态。未同步的历史指标仍是采集时快照，互动率、排行和浏览数不代表全量实时数据。时间线与提及流采集不完整、名单采样或指标更新受限时，应结合报表提示解读。
- **缺失指标与旧缓存**：缺失的浏览、赞、回复、转推/引用、书签与真实 0 分开记录；按所需字段已知的样本计算均值和互动率，并披露样本数。浏览为 0 时不能计算互动率，显示 `--`；无可用样本不计算相应评分。刷新只更新返回的字段，不用缺失字段覆盖已有测量。旧记录没有可用性元信息时保守视为未知，等待后续刷新补充；不删除旧数值，也不把它们冒称为已验证指标。该说明同步用于页面、复制、分享链接和 PNG。
- **主帖访问与时间桶**：只有根帖归属证据明确的回复才计入“我去评 TA 主帖／TA 来评我主帖”；楼中楼及旧记录缺少归属字段时不作肯定推断，原始回复活动数仍保留。48 小时统计以滚动起点划分 48 个小时桶，趋势图为同一起点的 24 个两小时桶，最后一桶包含窗口终点。
- **界面语言**：顶部原“已入库报表”位置改为语言选择，支持中文、English、日本語、한국어；登录页提供同步入口，默认中文，并记住本浏览器的选择。切换只更新系统界面文字与显示，不重新取数，不重置草稿、选中时间或滚动位置。昵称、简介、推文正文、文件名及算法 JSON 保持原文。所有翻译随静态资源提供，无付费翻译服务；分享文案先执行原隐私处理，再本地化。
- **查看已入库报表**：登录后仍可通过 `/?stored=true` 打开最近一次入库的本人报表，顶部“切回实时”返回正常同步。页面显示原采集时间，24 小时、48 小时、7 天和 30 天按同一入库快照计算。趋势图上方列出本周期非纯转推的总浏览、总互动及各自的已知样本数。点击“返回实时报表”可继续正常同步。
- **趋势图串推口径**：原创/引用柱包含串推楼层，明细单列楼层数并计入总动态，与浏览等指标的样本范围一致；主推原创数与回复数的业务定义不变。
- **部分样本的业务建议**：日均按实际已覆盖时长折算，并明确不是完整周期的真实整日结果。引用、提及及未能确认根帖归属的对话不冒充主帖互评，但会阻止“完全零互动”的错误清理建议。历史覆盖不足时暂停按零互动/单向付出建议取关。待回访包含尚未回应的评论；核心铁粉、活跃互暖和待回访是不同维度，可有重叠，三组都在战报页显示。
- **指标解释与隐私**：公开互动率使用公开赞、评、转推/引用、书签与浏览数计算，不等同于官方 Analytics Engagement rate。运营分、内容提示及 1–3% 参考区间属于本站启发式，不证明 For You 来源、影子封禁、平台权重或外链因果。隐藏回关率同时作用于图片、复制文案和发推链接，包含样本回关率及其附注。
- **时间范围与推文复盘**：顶栏仅保留四个时间范围；点击已确认不可用的范围时才显示现有解锁说明，权限加载失败不冒充未解锁。浏览偏低的复盘候选仅取当前报表周期内的独立主推，至少已发布 3 小时（配置的推荐间隔更长时按该间隔）、已知浏览不少于 100，并满足既有历史模型及实际互动率筛选。历史基线仍使用全部已采集样本；不足 6 个非连发有效样本不提示。候选与其他建议使用相同卡片，列出已采集浏览、历史单帖中位数并直达原帖，不据此推断平台限流或敏感词原因。旧报表的旧异常提示不再显示，无额外上游请求。
- **关注列表排序**：分类人数按已取得的关系证据显示；名单不完整时，已确认人数以“≥”标记，尚无已确认账号时显示“待核验”或“未确定”。三个分类都先显示已确认的蓝 V，再在组内按所选条件排序，默认按最近关注顺序。「TA 未回关／互关」使用本人关注名单次序，「我未回关」使用粉丝名单次序。亲密度沿用本周期既有评分、粉丝数量按已有资料，均从高到低排序。排序仅重排已加载数据，不触发额外采集。 关注与粉丝名单中的账号即使没有互动，也会在正常同步时补查缺失或已过期的蓝标。优先读取免费公开名单中的认证字段，每个方向每轮最多取一页；按稳定 ID 和用户名匹配，剩余账号沿用有预算限制的批量 API。未提供认证字段时保留未知，使用已有的 15 天认证缓存。最近顺序仅采用上游原名单的可靠次序；补齐资料和缺少次序元数据的旧缓存排在组内末尾，不使用注册日期或核验时间推算关注日期，正常关系图刷新后补全可用次序。[关注端点](https://docs.twitterapi.io/api-reference/endpoint/get_user_followings) · [粉丝端点](https://docs.twitterapi.io/api-reference/endpoint/get_user_followers)
- **关系操作状态**：点击“去取关／去回关／关注作者”只打开外部页面，不代表操作完成，不减少待办；以之后刷新取得的关系证据确认。旧版点击产生的乐观关注或本地已处理标记不再作为完成证据。
- **官方 API 契约**：请求按当前文档使用 `post.fields` 和 `referenced_posts` 扩展，解析兼容新旧帖子引用、扩展集合及计数字段。该兼容性有本地契约测试，仍不代表已验证真实官方端点的权限或现网行为。[官方帖子接口文档](https://docs.x.com/x-api/users/get-posts)
- **时区**：`xops.timezone`（环境变量 `X_TIMEZONE`）默认为 `Asia/Shanghai`。观察窗口和每日统计使用配置的时区。

## 配置文件说明（`src/main/resources/application.yml`）

### 免费公开数据优先读取

正常运行默认启用 `xops.fxtwitter-enabled`（环境变量 `X_FXTWITTER_ENABLED=true`），使用 [FxTwitter v2](https://docs.fxembed.com/api/introduction/) 读取公开账号资料、按时间窗口搜索的帖子与互动，以及已入库推文的公开指标。该服务无需 API Key；免费请求仅发送应用 User-Agent，不携带 TwitterAPI.io 密钥、X OAuth Token 或 Cookie。`/api/meta` 的 `freePublicDataEnabled` 表示当前开关。

- 免费资料、搜索或单帖读取报错或超时时，自动调用原 TwitterAPI.io 接口；免费阶段在本轮截止前 1.5 秒结束，给付费请求留出发起时间。搜索按原时间窗回退，跨页游标循环也会交由原接口核实。单帖缺失或与已知作者、发布时间、父帖冲突时，只补取对应 ID；双方证据仍冲突时保留旧记录。付费调用沿用原预算与取消规则。关注/粉丝名单、精确互关核验和批量用户信息仍使用原付费接口，所以当前是混合读取模式，仍需要现有 TwitterAPI.io 配置。官方登录、图片上传与发布继续使用原官方接口。
- 搜索结果必须满足作者、时间窗口、最新到最旧顺序和关联关系校验。免费结果包含无法还原事件时间的转推、无法核实根会话的回复、异常行或无效分页时，整页回退；免费游标与付费游标隔离，回退重新读取同一时间窗，按推文 ID 去重。同一秒跨页的数据继续按游标读完，避免不同页大小漏读窗口边界。多页游标循环或边界后续页失败时保留未覆盖区间。完成分页仅表示当前公开搜索返回范围已遍历，不保证 X 全量数据均可被搜索。
- 回复先用当前页和本人快照核对作者、发布时间、直接父帖及根会话。仍缺依据且一页至多涉及 4 个待查父帖时，并发查询 FxTwitter 免费讨论串，共用最多 1.5 秒，并为原接口预留时间；同一轮复用已完成的查询。只有父帖逐级相连、时间和作者吻合才接受结果；父帖过多、信息矛盾或根会话仍无法确认时，沿用原付费搜索。动态与互动搜索继续并发。
- `null`、缺字段和非法指标不作为有效 0，也不触发反复付费补取。已有有效读数保留旧值与旧采集时间；仍缺失的指标继续标为未知。公开浏览量不等于官方后台的曝光、点击或转化。免费超时、404、漏返回本身不移除已有帖子；仅在原付费补取已实际完成且返回有效推文数组后，按原付费批次的缺失记录规则处理已核验 ID，使每日统计一致。付费失败、未发出或缺少结果数组时继续保留旧记录；只有真正发出的请求才标记已尝试。
- 主帖优先使用 `raw_text.text` 原文，保留原短链接，避免免费接口的链接展开或媒体短链移除改变原有长度分类、外链统计及展示效果。
- 已知回复会话根不会因免费接口只提供直接父帖而被清空；重叠归并仅在发布时间、类型、父帖及互动对象一致时继承已知根，不推测缺失的根节点。详情必须与请求 ID、已绑定作者、已有发布时间及已知父帖相符；原先未知的父帖仍可补全。X 头像统一为原界面使用的 400 像素规格。正常指标下降按实际读数保留，不用历史最大值掩盖变化。取消请求会同时停止排队或在途读取，不再安排后续付费补取。
- 可设置 `X_FXTWITTER_ENABLED=false` 恢复原读取路径。`X_FXTWITTER_BASE_URL` 默认 `https://api.fxtwitter.com/2`；隔离 `preview` 模式明确关闭免费读取。付费密钥验证始终实际访问付费服务。

定向回归可运行 `mvn -Dtest=FxTwitterClientTest,FxTwitterIntegrationTest,FxTwitterParityTest,FxTwitterRecoveryParityTest,FxTwitterIdentityMetricParityTest,FxTwitterSearchBoundaryParityTest,FxTwitterAvatarParityTest,DailyMetricRefreshTest,MetricObservationAuditTest test`。这些用例使用本地模拟接口，检查数据映射、分页、费用回退与入库结果，并对照新旧数据链路的 24 小时、48 小时、7 天和 30 天完整报表，不调用真实 X 服务。

密钥通过环境变量或项目根目录的私密 `application-local.yml` 配置，前端不暴露任何 API Key 输入框。`src/main/resources/application.yml` 的凭据默认值为空，不包含本机密钥。

## 并发、付费请求与持久化保护

这些设置约束已有查询、授权与发布流程，不增加业务入口。前端继续使用原布局，不添加辅助徽章或说明区。

### 用户并发与请求边界

默认按登录身份维持 50 个活跃用户席位；每个用户最多同时执行 4 路受控请求。超过 50 个身份的合法请求先错峰、再公平排队，不会仅因第 51 人进入就被拒绝。队列仍有边界：默认最多 150 个等待请求、总等待 15 秒，耗尽后返回带 `Retry-After` 的 `503`，防止无限排队耗尽服务器。恶意路径、异常正文、跨站付费读取及洪泛按对应安全规则拒绝。

同一出口 IP 的用户分别计算账号额度。默认 IP API 洪泛阈值为每分钟 6000 次，授权入口为每分钟 150 次；付费同步入口的共享 IP 阈值按 `max(600, maxConcurrentUsers × 30)` 计算，默认 1500 次/分钟，每个账号仍最多 30 次/分钟。信任客户端 IP 的前提是正确配置本机反代；不得把任意客户端传来的代理头当作可信身份。

### 上游预算

每次外部 HTTP 请求在发出之前，先原子预留调用次数与估算金额；排队超时且尚未执行的任务从执行器中移除。所有读取、关系核验、OAuth 换取/刷新令牌、媒体上传及发帖共用预算。发出后的失败、超时或结果不确定不会自动退回预留额，避免重试放大费用。

| 环境变量 | 本地默认值 | 含义 |
|---|---:|---|
| `X_HOURLY_UPSTREAM_API_BUDGET` | 6000 | 每自然小时请求次数上限 |
| `X_DAILY_UPSTREAM_API_BUDGET` | 30000 | 每自然日请求次数上限 |
| `X_HOURLY_UPSTREAM_USD_BUDGET` | 10.00 | 每自然小时 USD 预留额上限 |
| `X_DAILY_UPSTREAM_USD_BUDGET` | 30.00 | 每自然日 USD 预留额上限 |
| `X_MONTHLY_UPSTREAM_USD_BUDGET` | 100.00 | 每自然月 USD 预留额上限 |
| `X_UNPRICED_UPSTREAM_REQUEST_RESERVE_USD` | 0.20 | 未明确公开单价的 OAuth/媒体请求单次预留值 |

金额是代码提供的保护默认值，**不是用户确认的预算、供应商账单或新增付费授权**。部署前应按实际承受额调整，并核对供应商消费上限及自动充值。任一限额为 `0` 表示停止外部调用；负数、非法金额及未知计费路径不按无限额度处理。周期使用 `xops.timezone`，与供应商账单周期可能不同。

预算保存在 `xops.disk-cache-dir` 下的 `upstream-budget.json`，配套 `upstream-budget.lock`；同一目录的进程通过文件锁共同检查和预留，重启不清零。应将该目录放在持久磁盘上，并随数据备份；不要删除这两份文件来重置额度；两者同时丢失或改用新目录会失去原记录，必须通过持久磁盘和备份避免。账本损坏、初始化标记仍在而账本丢失、锁定或落盘失败时，后续外部调用停止并返回可处理的服务错误。没有持久目录时仅允许 DEMO/本地模拟测试，真实上游调用会阻断。独立机器使用各自磁盘时，各账本不能构成集群总预算。

按已知端点、请求资源上限和公开价进行保守预留，不假定供应商一定去重或优惠。价格可能变化，未公开费项的预留也不是实测单价；应定期对照 [X API 官方价格](https://docs.x.com/x-api/getting-started/pricing) 与 [TwitterAPI.io 端点价格](https://twitterapi.io/pricing/details)。本控制不覆盖 GCE、Cloudflare、其他应用或泄漏密钥在外部产生的费用。Google Cloud 的普通 alerts-only 预算不自动封顶，spend cap 是否适用需按具体服务核对：[Cloud Billing 预算说明](https://docs.cloud.google.com/billing/docs/how-to/budgets)。

并发席位与消费预算是两个独立限制。当前官方 X 首屏配置包含两路各最多 100 个帖子及扩展资源、两路各最多 200 个关系用户和资料读取，按本实现最保守的资源上界合计预留可达 USD 18.01，超过默认每小时 USD 10；它可能因此中止首次真实采集，而已有快照仍可读取。这是费用保护的明确取舍，不代表实测账单就是该金额。上线时应结合实际供应商、账号数据量与用户确认的预算选择限额，不能用提高预算来冒充性能优化。

### 发布、存储与会话

定时编辑区显示最近已知的本人原创／引用主帖及已确认发布记录。手动时间和快捷预设使用同一浏览器本地时区。普通账号执行队列间隔和业务额度校验，已绑定的作者账号可自行排期。

定时任务的“复制”仅复制保存的原始正文，保留换行、空格及正文内的链接，不附带状态、时间、媒体或发布地址。移动端改期保留原时间输入节点，队列刷新和服务端校验失败不收起选择器；时间错误显示在输入框下方。保存请求发出后重新操作时间选择器，旧响应也不会覆盖或关闭新编辑。主动取消、切换筛选、删除当前任务或未继续编辑时保存成功，才结束当前编辑。

草稿转入定时编辑区时优先填入空白条目，否则追加到现有批次；达到既有限额时保留原内容并就地提示。正文、时间与配图在同一账号、同一浏览器标签页中暂存，支持刷新和授权往返恢复，恢复窗口为24小时；关闭标签页或浏览器清理存储不承诺恢复。图片存入有界的 IndexedDB，沿用既有条数与单图大小限制；失败时明确提示，待写入图片尚未保存时提供离开保护。恢复过程有超时边界，不覆盖后续输入或另一个账号的状态。添加或删除图片只更新媒体区域，增删草稿复用原输入节点。

创建、批量创建、授权和队列操作错误显示在对应操作区域，校验错误关联具体输入字段。任务列表区分读取中、空列表、读取失败和限流等待；遵守服务端 Retry-After，等待期间只更新显示，不增加请求。提交与改期设置有界等待，结果不确定时保留草稿或编辑状态，通过既有幂等标识及只读任务查询核对，不自动重发写请求。清空有内容的草稿、移除草稿、取消定时与删除记录要求一次简短确认；“放弃修改”和“取消定时”明确区分。

模块切换保留各自滚动位置，浏览器前进后退恢复相应模块。粉丝与互动列表按稳定账号键复用未变化行，避免加载更多或筛选时反复丢失焦点；“亲密度”统一优先比较互动分数。打开 X 操作不改写本站关系结论，实际关系仍以已同步数据为准。登录检查和退出操作即时显示进行中或失败状态；退出得到服务端确认后才清除该账号草稿。

后端创建、批量创建及改期在取得账号锁并读取队列后重新读取当前时间，防止等待期间失效的时间被旧校验放行。格式不正确的 JSON、字段类型和时间参数返回可处理的400响应；批量提交继续保持原子性，失败不留下部分任务。

默认每账号每天最多 24 次发布尝试；发送前持久化占用额度，失败或结果不确定也计数，删除任务历史和重启不能清零。上游可能已发布而本地保存失败时，保留需要确认的状态，避免盲目自动补发。同账号发送串行，不同账号使用有界后台执行队列。

每账号最多保留 500 个发布任务、256 MiB 媒体；全局上传预留磁盘余量 512 MiB，并校验媒体大小与摘要。这些保护不自动删除用户历史。快照、队列、令牌及会话写入采用受控替换；损坏队列不会被当作空队列覆盖，保存失败不会伪装成成功。

HttpSession 空闲超时默认 1 小时，持久登录 Cookie/加密记录继续保留最长 400 天滑动续期；只接受 Cookie 会话，拒绝 URL 会话凭据。同一旧 Cookie 的并发恢复复用会话，注销撤销整个恢复家族。生产仍需配置 HTTPS、Secure Cookie、受限源站入口及系统资源边界。

## 私人内容助手

使用 CommandCode 时，设置 `X_CONTENT_ASSISTANT_MODEL_PROVIDER=commandcode` 和 `X_CONTENT_ASSISTANT_COMMANDCODE_API_KEY`。默认地址为 `https://api.commandcode.ai/provider/v1`，可用 `X_CONTENT_ASSISTANT_COMMANDCODE_BASE_URL` 覆盖。页面填写模型、协议及实际可用上下文长度，联网研究使用模型支持的 Responses 搜索。[CommandCode Provider API](https://commandcode.ai/docs/provider)

非密钥设置接口 `POST /api/content-assistant/settings` 接受可选的 `bindings` 对象。可按 `CLASSIFY`、`SCORE`、`STYLE`、`RESEARCH`、`DRAFT` 或 `OPTIMIZE` 分别覆盖模型、协议、上下文、超时及输出长度。未填写的字段继承主模型，研究角色还可继承页面上的研究模型配置。能力检查按配置版本保存结果。

选择来源的「研究并生成」启动后台研究。系统保存取得的来源、未核实事项和稿件版本。首次写稿需先取得并学习本人的合格历史文字，页面显示实际条数。模型或网络中断可查看阶段并明确重试。进入定时编辑区后仍须提交，提交时固定稿件版本、待发文字和时间。排期后修改草稿，可主动更新仍待发送的队列任务。

使用「生成新版本」时，可在改稿要求里明确写出「180–240 个汉字」或「不新增数字」。首次校验未达标时，助手自动修订一次并再次校验。仍未达标时，原稿保留，可在任务区查看校验结果和候选稿。

私有数据在 `X_DISK_CACHE_DIR/content-assistant/assistant.sqlite`，按北京时间每天生成一致备份，最近 7 份位于同目录的 `backups/`。恢复时先停用此实例，用一致备份恢复数据库，再对照原定时队列核对发布回执。助手只读取、关联已有队列回执。生产日志、供应商实际覆盖及发布成功以目标环境的回执为准。
